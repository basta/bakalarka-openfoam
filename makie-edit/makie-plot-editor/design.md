Design Document: Interactive Makie Plot Editor
Version: 1.0
Date: May 6, 2025

1. Project Aims & Goals
   The "Interactive Makie Plot Editor" is a web-based application designed to provide users with an intuitive and interactive environment for visually refining plots generated by Julia's Makie.jl plotting library.

Primary Goals:

Visual Interactivity: Allow users to see a live preview of their Makie plot and modify its visual attributes (e.g., colors, line styles, fonts, labels, titles, layout) through a graphical user interface.

Real-time Feedback: Changes made in the UI should be reflected in the plot preview in near real-time, enabling an iterative and exploratory workflow.

Inspector Panel: Provide a comprehensive inspector panel, likely a tree view, where users can access and modify various plot properties in an organized manner, similar to inspector panels in IDEs, game engines, or CAD tools.

Makie Integration: The application's backend will be powered by Julia and Makie.jl, ensuring that the plot modifications are true to Makie's rendering capabilities.

Code Generation (Future Goal): Ideally, the application should be able to generate the Julia Makie code corresponding to the current visual state of the plot, allowing users to reproduce the plot programmatically in their own Julia scripts.

Usability: Focus on a user-friendly interface that is easy to navigate and understand, even for users who might not be deeply familiar with all of Makie's programmatic options.

Extensibility: Design the system to potentially support various Makie plot types and a wide range of customizable attributes.

Target User:

Julia users who work with Makie.jl for plotting and desire a more visual and interactive way to fine-tune the appearance of their plots without needing to repeatedly modify and re-run Julia code for minor visual adjustments. This could be particularly useful for preparing publication-quality figures or for exploring different visual styles.

2. Architecture Overview
   The application will consist of two main components:

Frontend: A web-based user interface (HTML, CSS, JavaScript) responsible for displaying the plot and the interactive control panel. It will communicate with the backend via WebSockets.

Backend: A Julia server utilizing Makie.jl for plot generation and modification. It will host a WebSocket server to handle communication with the frontend.

3. Communication Scheme
   Communication between the frontend and backend will primarily occur over WebSockets, with messages formatted as JSON objects. This allows for persistent, bidirectional, and real-time interaction.

The detailed protocol is outlined in the "Communication Protocol: Makie Plot Editor" document (ID: makie_app_comm_protocol_v1). Key aspects include:

Message Structure: Each JSON message will have a type (e.g., SET_PLOT_ATTRIBUTE, PLOT_UPDATE) and a payload containing message-specific data.

Frontend to Backend Messages:

REQUEST_INITIAL_PLOT: To load the initial plot.

SET_PLOT_ATTRIBUTE: To change a specific attribute of a plot element (e.g., line color, axis label font size). The payload will specify the target element, attribute name, and new value.

APPLY_THEME: To apply a predefined Makie theme.

EXPORT_PLOT: To request plot export in various formats (PNG, SVG, PDF, Julia code).

(Future) UNDO_ACTION, REDO_ACTION, LOAD_DATA.

Backend to Frontend Messages:

PLOT_UPDATE: To send the updated plot to the frontend. This could be an image (PNG/SVG) or, if using WGLMakie.jl/JSServe.jl, commands to update the WebGL scene directly.

EXPORT_RESULT: To send the exported plot data or code.

INITIAL_PLOT_STATE: To provide the initial plot and the state of its attributes for populating the inspector.

STATUS_MESSAGE: For general feedback.

ERROR_MESSAGE: To report errors.

Role of JSServe.jl / WGLMakie.jl:

If JSServe.jl and WGLMakie.jl are utilized:

Many direct attribute modifications might be handled by JSServe's built-in synchronization of Julia Observables with frontend elements. This can reduce the need for some explicit SET_PLOT_ATTRIBUTE / PLOT_UPDATE messages for simple changes.

The explicit protocol will remain crucial for initial plot loading, complex actions (e.g., theme application, export), managing the dynamic population of the inspector panel, and error/status reporting.

WGLMakie.jl would enable client-side rendering, making plot updates more efficient by sending scene modifications rather than full images for many interactions.

Element Identification:

A consistent mechanism for identifying plot elements (targetId in messages) between the frontend and backend will be established. The backend may provide a list of plottable elements and their unique IDs upon initial plot load, which the frontend inspector will use.

4. Key Technologies (Initial Plan)
   Frontend:

HTML5

CSS3 (potentially with Tailwind CSS via CDN for styling)

Vanilla JavaScript (for UI logic, DOM manipulation, and WebSocket client)

Backend:

Julia

Makie.jl (with a suitable backend like CairoMakie for image generation or WGLMakie.jl for interactive web rendering)

HTTP.jl & WebSockets.jl (for the WebSocket server, or JSServe.jl which uses these internally)

JSON3.jl (for JSON processing)

5. Future Considerations
   Support for a wider range of Makie plot types and attributes.

User accounts and saving/loading plot configurations.

More advanced data loading and manipulation capabilities within the app.

Direct manipulation of plot elements on the canvas (e.g., dragging legend).

Integration with a full JavaScript framework (React, Vue, Svelte) for the frontend if complexity grows significantly.

This document will be updated as the project evolves.
